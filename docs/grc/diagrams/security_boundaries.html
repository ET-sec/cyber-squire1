SECURITY BOUNDARIES

Layered trust model of the platform. Every boundary crossing is named, carries its authentication mechanism, and where the control was proven, the receipt of the forced failure. Verified 2026-08-31.
LANE A: HUMANS
UNTRUSTED: PUBLIC INTERNET
Operators and end users in browsers. Assumed hostile until authenticated.
CROSSING 1: HUMAN AT THE EDGE
Cloudflare Access single sign-on: identity provider login before any request reaches an application, with WAF and DDoS filtering in the same hop. The origin address is never published; the edge hostname is the only door.
DEFEATS: anonymous probing, credential stuffing, stolen-URL access
EDGE: CLOUDFLARE
Authenticated sessions only past this line. DNS, WAF, Access policy, tunnel termination.
CROSSING 2: EDGE TO ORIGIN
Outbound-only tunnel: the origin authenticates outward to the edge with a tunnel credential and keeps zero listening service ports. There is no inbound path to reach.
DEFEATS: direct-to-origin bypass, internet-wide port scans
LANE B: THE PIPELINE
UNTRUSTED: AUTOMATION
GitHub Actions runner in a public repo. Any fork can run workflows; none of them can reach the cloud.
CROSSING 3: PIPELINE TO CLOUD
OIDC token exchange (RFC 8693): a GitHub-signed identity token is exchanged for a short-lived OCI session token. Trust is pinned to this repo and its main branch, the mapped principal is read-only, and no cloud key is stored anywhere.
VERIFIED: wrong-branch token exchange refused, HTTP 401 DEFEATS: leaked long-lived cloud keys, fork pipeline abuse
CI PRINCIPAL: READ-ONLY
Exists for minutes per run. Plans, compares, alerts. Cannot mutate infrastructure or wedge the state lock.
CONVERGENCE: BOTH LANES END AT THE SAME PERIMETER
Humans arrive through the tunnel as application traffic. The CI principal arrives at the cloud control plane as a read-only observer. Neither path carries a standing credential.
HOST BOUNDARY: OCI INSTANCE INSIDE THE VCN
Ampere A1 ARM instance, Always Free. Security list is deny-by-default: SSH only from operator allow-listed CIDRs as break-glass, nothing else inbound.
LIVE workload
PostgreSQL 16 + pgvector, n8n, Cloudflare tunnel client. The only three running containers.
Designed, not running
Vault, Keycloak, Teleport, Falco, Datadog, Langfuse, Ollama, NeMo Guardrails, Squire agent.
PENDING ARM REBUILD
CROSSING 4: HOST TO STORAGE
Instance principal: the instance itself is the identity; the nightly backup job holds no stored cloud credential. Its policy grants create, read, and inspect on the backup bucket only. Delete does not exist in the grant, because the writer holding delete rights IS the ransomware scenario.
VERIFIED: owner delete refused, retention rule error DEFEATS: stolen-host credential abuse, backup destruction
DATA BOUNDARY: OBJECT STORAGE
No public access on either bucket. Names and addresses stay out of the public repo.
Terraform state bucket
Versioned, with native locking: the lock is an atomic create-if-absent object.
VERIFIED: concurrent run refused, HTTP 412 lock conflict
Backup bucket
30-day retention rule: objects immutable until the window expires, even for the account owner. Restore-tested monthly.
VERIFIED: latest restore, 76 tables in 5 seconds
CROSSING 5: DATA TO KEYS
Key-wrap API: both buckets reference a customer-managed key in OCI Vault. Envelope model: the key encryption key never leaves the KMS and only wraps per-object data keys, so rotation re-wraps a handful of keys and never re-encrypts the data.
VERIFIED: key rotation exercised, data intact, old versions still unwrap DEFEATS: bulk plaintext exposure from a storage compromise
KEY BOUNDARY: OCI VAULT KMS
Customer-managed AES-256 key. Innermost ring: nothing crosses inward, wrap and unwrap requests come to it.

A secret or unreviewed change must beat six independent layers before it survives on the main branch. The last layer catches what never went through the pipeline at all.
