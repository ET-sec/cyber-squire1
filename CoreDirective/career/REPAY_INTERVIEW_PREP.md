## 2. Splunk Enterprise Security (ES) Crash Course

**This is where you MUST sound fluent.** Splunk Core and Splunk ES are different products. The JD specifically says ES. Here is what you need to know by name:

### Key ES concepts and vocabulary

| Term | What it means | What to say about it |
|------|---------------|----------------------|
| **Notable events** | Alerts generated by correlation searches in ES. Shown in the Incident Review dashboard. | "I tune notable events to cut false positives and prioritize high fidelity signals." |
| **Correlation searches** | Saved searches that generate notables when they match. Run on a schedule. | "I write correlation searches against the Common Information Model and tune them over time." |
| **CIM (Common Information Model)** | Splunk's normalized schema for log data (Authentication, Network_Traffic, Malware, etc.) | "CIM mapping is the foundation — if your data is not normalized to CIM, ES correlation searches will not work cleanly." |
| **Data models** | Accelerated CIM datasets ES uses for fast searches. | "I understand data model acceleration is what makes ES searches performant at scale." |
| **Risk Based Alerting (RBA)** | Newer ES feature. Instead of one alert per detection, you assign risk scores to objects (users, systems). When a risk object crosses a threshold, you get one high fidelity notable. | "RBA is how you cut alert fatigue — instead of 500 low quality notables you get 10 high confidence ones based on accumulated risk." |
| **Adaptive response** | ES's SOAR-lite: auto-actions on notables (enrich with threat intel, run scripts, ticket creation). | "I would wire adaptive response to hand off to an agentic SOC workflow for enrichment and triage." |
| **Threat intel framework** | ES's built-in IOC management (stix/taxii, custom feeds, manual upload). | "The threat intel framework is where I would operationalize new IOCs and IOAs." |
| **Content Management** | ES's catalog of correlation searches, dashboards, and use cases. | "Content management is where I version and maintain detection logic." |
| **Detection as Code** | Managing Splunk content in Git with CI/CD instead of the UI. | "I would maintain ES content as code in Git, gated by PR review and a test pipeline — same pattern I use for Terraform and OPA now." |

### Key vocabulary

| Term | What it means |
|------|---------------|
| **Agentic SOC** | An AI-driven security operations model where LLM agents handle tier 1 triage, enrichment, investigation, and recommendation. Humans approve high impact actions. |
| **Multi-agent workflows** | Multiple specialized LLM agents (triage agent, enrichment agent, responder agent) coordinating through a shared state or orchestrator. |
| **RAG (Retrieval Augmented Generation)** | LLM retrieves relevant context from a vector DB before answering. Key for SOC: retrieve similar past incidents, runbooks, threat intel. |
| **Vector search** | Semantic similarity search over embeddings. Useful for "find past incidents like this one." |
| **Orchestration frameworks** | LangChain, LangGraph, n8n, Prefect, Temporal. You use n8n, which is one of them. |
| **Guardrails** | Controls on LLM output: NeMo Guardrails, prompt filtering, output validation, tool gating. You have done this. |
| **Tool use / function calling** | LLM calls deterministic tools (Splunk API, VirusTotal, ticket system) instead of answering from memory. |
| **Human in the loop** | Human approval gate before high impact actions (containment, blocking, termination). |

## 4. Threat Hunting — Your Framework Answer

The JD mentions proactive threat hunting across endpoints, network, cloud, and identity. Most candidates blank on this. Here is a clean framework to anchor on:

### The hypothesis driven threat hunting loop

1. **Form a hypothesis** based on threat intel, a specific TTP, or a gap in detections. Example: "An attacker is abusing AWS STS to assume roles from unexpected source IPs."
2. **Identify the data sources** needed to test it. Example: CloudTrail, VPC flow logs, GuardDuty findings.
3. **Build the query** in Splunk or your SIEM. Baseline normal, look for anomalies.
4. **Investigate the outliers** manually. Pivot across indexes. Look at who, what, when, where.
5. **Document findings** — true positive, false positive, new detection opportunity.
6. **Productionize** the hunt into a correlation search if it is worth keeping.

### Your verbatim answer if asked how you hunt

> "Hypothesis driven. I start with a specific TTP from ATT&CK or a piece of threat intel, identify which data sources cover it, write a query to baseline normal and surface anomalies, pivot on the outliers, document the findings, and if the hunt is valuable I convert it into a correlation search so the detection is permanent. For cloud hunts specifically I focus on CloudTrail, VPC flow logs, and identity events, because that is where modern attackers live. For endpoint I focus on process trees, parent-child anomalies, and persistence mechanisms."

### MITRE ATT&CK fluency

The JD asks for "MITRE ATT&CK fluency" and "converting adversary TTPs into detections." Be able to name these tactics in order (top row of the matrix):

1. **Reconnaissance** (OSINT, scanning)
2. **Resource Development** (infrastructure setup)
3. **Initial Access** (phishing, exploit public facing app, valid accounts)
4. **Execution** (command and scripting interpreter, user execution)
5. **Persistence** (scheduled tasks, registry, startup folder)
6. **Privilege Escalation** (token manipulation, UAC bypass)
7. **Defense Evasion** (obfuscation, masquerading, indicator removal)
8. **Credential Access** (credential dumping, brute force, keylogging)
9. **Discovery** (system info, account enumeration, network scanning)
10. **Lateral Movement** (remote services, pass the hash, RDP)
11. **Collection** (screen capture, audio, keylogging)
12. **Command and Control** (application layer protocols, encrypted channels)
13. **Exfiltration** (over C2, exfil over web service)
14. **Impact** (data destruction, encryption, defacement)

You do NOT need to memorize every technique. You DO need to be able to pick one tactic and give an example detection. Try this:

> "For credential access, one detection I'd build in Splunk is anomalous failed authentication followed by a successful one from the same source. It catches password spray and brute force attempts. In CloudTrail that is a query against AssumeRole and ConsoleLogin events. In AD that's 4625 followed by 4624 from the same source IP. The detection writes into the risk based alerting framework with a risk score proportional to the sensitivity of the target account."

### MITRE ATLAS (the AI version)

This is your differentiator. ATLAS is MITRE's ATT&CK matrix for adversarial ML and AI systems. You already use it.

> "ATLAS is the ML and AI version of ATT&CK. Tactics include ML Model Access, Initial Access through prompt injection, ML Attack Staging, Exfiltration of model weights or training data, and Impact through model evasion or poisoning. I use ATLAS as the threat model when I red team my agentic platform, in parallel with OWASP LLM Top 10."

## 6. Incident Response — The Answer That Got You at Resilience

**THIS is the one you need to rehearse out loud.** The Resilience interview burned you on IR tool specifics. Let us fix that now.

### The canonical NIST 800-61 IR lifecycle (memorize)

1. **Preparation** — runbooks, tooling, training, contact lists, detection content
2. **Identification** — alert fires, analyst triages, confirm vs false positive
3. **Containment** — isolate the host, disable the account, block the IP, revoke the token
4. **Eradication** — remove the malware, rotate the credentials, patch the vuln
5. **Recovery** — restore service, monitor for recurrence, validate clean state
6. **Lessons Learned** — post incident review, detection improvements, runbook updates

### Your verbatim IR answer (practice out loud 5 times)

> "I follow NIST 800-61. Preparation is runbooks and detection content. Identification is alert triage in the SIEM — in my case Splunk — where I pivot across auth, network, and endpoint indexes to build a timeline. Containment depends on the indicator: isolate a host through EDR, disable an account in AD or Keycloak, block an IP at the firewall or Cloudflare, or revoke a token in AWS. Eradication is removing the persistence mechanism, rotating credentials, and patching the vulnerability. Recovery is restoring clean state and monitoring for recurrence. Lessons learned feeds back into new detections and runbook updates. My best example is at Texaco where I built a 6 step IR runbook that took our average containment time from 8 hours down to 90 minutes."

### If they ask for a specific incident walkthrough

Use your Texaco POS skimmer story. You investigated it. You contained it. You have real details:

> "We had a POS skimmer investigation at one of our retail locations. Detection came from a combination of Splunk alerts on anomalous outbound traffic and a physical inspection tip. I pulled Wireshark captures to confirm the device was beaconing, isolated the affected register from the network, preserved the evidence, coordinated with our payment processor for card brand notification per PCI DSS incident response requirements, rotated all credentials that touched that terminal, and validated the clean state with a follow-up network scan. Post incident I tightened the segmentation — that was part of why I rebuilt the flat network into 4 VLANs separating POS payment traffic from everything else. Lateral movement went to near zero after that."

**This is a real story from your resume. Use it. Don't invent one.**

### Containment actions by surface (in case they drill)

| Surface | Containment action |
|---------|---------------------|
| Endpoint | Isolate host through EDR (Crowdstrike, SentinelOne, Defender) |
| Network | Block IP at firewall, Cloudflare, or router ACL |
| Identity | Disable account in AD or IdP (Okta, Azure AD, Keycloak), revoke tokens, force password reset |
| Cloud | Revoke IAM credentials, rotate access keys, stop or isolate EC2, revoke STS tokens |
| Email | Quarantine, block sender, remove messages from mailboxes |
| Application | Disable user session, revoke API token, feature flag shutdown |
