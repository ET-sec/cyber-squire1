CoreDirective · Job Pipeline Tracker · System Spec

Pipeline of record. Comp calculator. Cross-sheet integrity layer.

A multi-tab Google Sheet that tracks every active opportunity, auto-converts gross pay into Georgia 2026 net across hourly, weekly, monthly, and annual views, and cascades inserts and deletes across every dependent tab. Built so a single Claude Code CLI command can spawn or remove a full opportunity record.

01 System overview

The tracker is one workbook doing three jobs at once.

Pipeline of record spine

Every active opportunity has a row in Pipeline_Master AND a dedicated tab. Master row = at-a-glance. Tab = deep record.

Comp calculator math

Anything entered as gross hourly or annual auto-converts to net via the Georgia 2026 TaxRate LAMBDA. Hourly, weekly, monthly, annual all derived from one source.

Cross-sheet integrity cascade

Insert or delete in Pipeline_Master cascades to per-job tab, comp row, recruiter log, action list, JD entry. One write, one delete, everywhere consistent.

Design intent

A single Claude Code CLI command ("add Milestone Tech to the pipeline") triggers row insert, per-job tab spawn, recruiter log append, action list seed, and comp row insertion with formulas filled. A single delete cascades the removal. Apps Script bound to the workbook does the cascade work, not Claude.

Behavior on row insert

  1. Apps Script onInsert(row) fires.
  2. Spawns a new tab from Per_Job_Template using B as the tab name.
  3. Appends a row to Comp_Analysis with B as Pipeline display, G as Type, J/K/L feeding the comp formulas.
  4. Appends a row to Recruiter_Log if N is non-empty.
  5. Appends a row to Action_List from S+T.
  6. Creates the prep folder on disk via gws-cli or gcloud (out-of-spreadsheet).
  7. Appends an entry to JDs_Full keyed by B.

Behavior on row delete (the cascade)

Cascade contract

Deleting a Pipeline_Master row removes that opportunity from every place it exists. No orphan tabs, no orphan log rows, no orphan actions.

  1. Apps Script onDelete(row) fires.
  2. Captures B (company_key) before the delete completes.
  3. Removes the matching tab named B.
  4. Removes the matching row from Comp_Analysis.
  5. Removes any rows from Recruiter_Log where company_key = B.
  6. Removes any rows from Action_List where company_key = B.
  7. Removes the JDs_Full entry keyed by B.
  8. Archives all of the above to a hidden Archived_<date> tab so it can be undone within 7 days.

Tax formula — named LAMBDA

Georgia, single filer, 2026. Federal progressive + Georgia flat 5.39% + FICA + optional SE add-on for 1099.

TaxRate = LAMBDA(type, gross,
  LET(
    federal_taxable, MAX(0, gross - 15000),
    federal_tax,
      IF(federal_taxable <= 11925, federal_taxable * 0.10,
      IF(federal_taxable <= 48475, 1192.50 + (federal_taxable - 11925) * 0.12,
      IF(federal_taxable <= 103350, 5578.50 + (federal_taxable - 48475) * 0.22,
      IF(federal_taxable <= 197300, 17651 + (federal_taxable - 103350) * 0.24,
      IF(federal_taxable <= 250525, 40199 + (federal_taxable - 197300) * 0.32,
      IF(federal_taxable <= 626350, 57231 + (federal_taxable - 250525) * 0.35,
                                    188769.75 + (federal_taxable - 626350) * 0.37)))))),
    ga_taxable,    MAX(0, gross - 12000),
    ga_tax,        ga_taxable * 0.0539,
    fica_ss,       MIN(gross, 176100) * 0.062,
    fica_medicare, gross * 0.0145 + MAX(0, gross - 200000) * 0.009,
    se_addon,      IF(type = "1099", gross * 0.0765, 0),
    total_tax,     federal_tax + ga_tax + fica_ss + fica_medicare + se_addon,
    total_tax / gross
  )
)

One function. Every row uses it. Update Settings_Tax when 2027 brackets drop, every row recalculates.

04 Data flow

When Claude Code adds a new opportunity

  1. Claude Code parses the JD (URL, paste, screenshot).
  2. POSTs to n8n master-cmd webhook with action sheets, payload includes sheet_id, target_tab Pipeline_Master, row payload (22 columns), JD text for JDs_Full, recruiter touch for Recruiter_Log.
  3. n8n writes the row to Pipeline_Master.
  4. Apps Script onInsert fires the cascade: spawns per-job tab, inserts Comp_Analysis row, JDs_Full row, default Action_List rows, Recruiter_Log row.
  5. Apps Script returns success/error to n8n which logs to Datadog.
  6. Claude Code receives the response and creates the local prep folder on disk.

When Emmanuel manually edits a cell

  1. Apps Script onEdit fires.
  2. If the edited cell is in Pipeline_Master, propagates the change to the per-job tab and Comp_Analysis row via INDEX/MATCH dependents.
  3. Updates updated timestamp on the affected row.

When a row is deleted

See section 3.1 cascade behavior. Apps Script captures the company_key before the delete completes, then sweeps every dependent tab.

05 Apps Script triggers

function onEdit(e) {
  const sheet = e.range.getSheet().getName();
  if (sheet === "Pipeline_Master") {
    propagateMasterEdit(e);
    stampUpdated(e);
  } else if (isPerJobTab(sheet)) {
    stampJournalIfNotesEdit(e);
  }
}

function onChange(e) {
  // captures structural changes including row inserts and deletes
  if (e.changeType === "INSERT_ROW") {
    spawnDependents(e);
  } else if (e.changeType === "REMOVE_ROW") {
    cascadeDelete(e);
  }
}

Triggers are bound to the spreadsheet, not specific user actions. They fire whether Claude Code wrote the row or Emmanuel typed it.

06 Design system

CoreDirective brand: black void + electric green. Tactical, restraint reads as intelligence. But one shade of green flat across every cell is unreadable. The system below uses layered tones, secondary accents, and clear hierarchy so glanceability stays fast.

Why differentiation matters

Emmanuel reads this sheet 5+ times a day during a job hunt. If every cell is the same green on the same black, the eye cannot find the offer row vs the rejected row, the warning vs the data, the title vs the body. Differentiation is not decoration. It is signal.

6.3 Layout and spacing

  • Row height: 28px data rows, 36px section headers, 48px tab title banner.
  • Padding: 4px left/right indent on every cell. No values flush against borders.
  • Borders: No gridlines visible. Section headers carry a 1px bottom border in signal.dim. Data tables carry no borders, separation comes from row banding.
  • Row banding: Alternating bg.void and #0f141b (one shade lighter). Banding starts under the column header, not from row 1.
  • Frozen rows: Tab title banner (row 1) and column header row (row 2) frozen on every tab.
  • Frozen columns: Pipeline_Master freezes A-C. Per-job tabs freeze A-B.
  • Merged cells: Only for tab title banners and section dividers. Data cells never merge.

6.6 Brand audit checklist (per tab)

  1. Background: Cell A1:Z1000 default fill is bg.void, not white.
  2. Font: Default cell font is JetBrains Mono 10pt for data, Inter 10pt for long text. No Arial, no Calibri.
  3. Title banner: Row 1 merged, height 48px, fill bg.deep, text signal.bright 14pt Bold all caps.
  4. Column headers: Row 2 fill bg.rise, text signal 10pt Bold.
  5. Frozen rows: Rows 1-2 frozen.
  6. Number formats: Currency, percent, date, hourly all match section 6.5.
  7. Status conditional formatting: Applied to status column with rules in section 6.4.
  8. Row banding: Alternating bg.void and #0f141b from row 3 down.
  9. No defaults: No cell uses default Sheets styling.
  10. Empty cells: Empty cells carry bg.void fill, not default white.
  11. Body text not all green: Long-form notes and descriptions use ink (#e6edf3), not signal green. Green is reserved for data.
  12. Hyperlinks: Override default blue to info (#58a6ff) underlined.

Every tab clears all 12 checks before it counts as compliant.

08 Open questions

  1. Tax baseline: Single, married, or HoH? Spec assumes single. Adjust standard deduction and brackets if married/HoH.
  2. Pre-tax deductions: Comp_Analysis showed $74/hr net on $85/hr Contract C2H, implying ~13% effective tax. Real math gives ~30%. Is the formula assuming health + 401k pre-tax subtraction, or is row 7 just broken? Most likely broken.
  3. CURRENT BASELINE: Currently $0/mo because between roles. Default to last role's monthly net so deltas are meaningful, or stay at $0?
  4. Cascade timing: Hard delete vs archive-on-delete? Recommend archive-on-delete with 7-day undo window.
  5. Per-job tab template: Does Per_Job_Template already exist or do I draft it from section 3.3?
  6. Hidden tabs: Are Pipeline_Master, Settings_Tax, Settings_Conventions actually present, or do I spec them as new tabs?
